# Материалы MAS: инструкция для коллеги

Дата передачи: 6 сентября 2026 года. Здесь собраны уже выполненные проверки
мультиагентной системы (MAS): резюме, вопросы и ответы, оценки для рекрутера,
сохранённый фидбэк и ошибки незавершённых прогонов.

Для чтения результатов не нужны Python, запуск приложения, API-ключи или платные
вызовы модели. Для технического продолжения передайте агенту
[отдельную инструкцию](mas-results-agent-instructions.md).

## 1. Получить материалы

В репозитории `VladimirMaximov/ai-interviewer`, ветка `main`, откройте папку
`deliverables/ai-technical-interview/`. Скачайте файл
`mas-analysis-complete-materials-2026-09-06.zip` через кнопку Download / Download raw
file и распакуйте его. Можно также скачать весь репозиторий через Code → Download ZIP.

Если репозиторий уже клонирован и в нём нет незакоммиченных изменений:

```bash
git switch main
git pull --ff-only origin main
```

Внутри архива откройте папку `mas-analysis-2026-09-06`, затем `00_README.md`.
Файлы `.md` читаются в редакторе Markdown или обычном текстовом редакторе;
`.json` содержат исходные структурированные результаты.

Обе инструкции также находятся внутри архива:
`mas-results-handoff.md` и `mas-results-agent-instructions.md`.

## 3. Правильно прочитать результаты

| Проверка | Фактический результат | Что он означает |
|---|---|---|
| Обезличенный кейс, 5 сентября | 7,61/10 на 9 synthetic-ответах | Оценка симуляции, которую нельзя переносить на реального кандидата |
| Классификатор 10 кандидатов, первая версия | 7/10 совпадений с эталоном | Результат отдельного оценщика ответов |
| Классификатор 10 кандидатов, v2 | 10/10 совпадений на том же датасете | Регрессионная проверка после калибровки; не независимый holdout |
| Полный MAS на 10 кандидатах, последний запуск | 0/10 завершённых конвейеров | Технический сбой; не десять отрицательных оценок кандидатов |
| Замер одного интервью | 52,310 секунды до остановки | Не время успешно завершённого интервью; итоговый фидбэк не создан |

В последнем полном MAS у `PY-001` сохранились четыре ответа, их оценки и итоговый
профиль, но не успешный фидбэк. У `PY-002`–`PY-010` сохранились резюме, однако
прогон остановился на анализе резюме. Провайдер VseGPT сообщил неположительный
баланс. Оценки отдельного классификатора не заменяют эти отсутствующие этапы.

`confidence` означает уверенность модели, `coverage` — покрытие критериев
доказательствами. `overall_readiness` и `value` представлены в исходных шкалах;
их нельзя читать как готовые баллы из десяти или процент точности системы.

Все ответы в основных кейсах synthetic/mock. У обезличенного кейса резюме основано
на предоставленной профессиональной информации, но ответы придуманы для проверки.
У десяти synthetic-кандидатов резюме изначально короткие; весь доступный текст
включён в архив.

## 4. Как проверить конкретного кандидата

1. Прочитайте вакансию и резюме. Отделите заявления резюме от подтверждённого
   ответа на вопрос.
2. Сопоставьте каждый вывод AI с полным ответом и цитатой или идентификатором
   evidence. Отсутствие доказательств отметьте как недостаток информации.
3. Проверьте соответствие вакансии отдельно от общей технической оценки.
   В исходной вакансии есть расхождение между порогами 3+ и 5+ лет;
   трактовку должен определить нанимающий менеджер.
4. Прочитайте фидбэк кандидату и отметьте фактические ошибки, неподтверждённые
   советы или противоречия оценке. Отсутствующий фидбэк не восстанавливайте
   догадками.
5. Запишите решение рекрутера и решение нанимающего менеджера отдельно от AI.
   В переданных материалах решения людей не зафиксированы. Фидбэк — черновик,
   подтверждения его публикации кандидату нет.

Для передачи замечаний используйте такой формат:

```text
Кейс и запуск:
Файл, вопрос или evidence ID:
Вывод AI:
Цитата из исходного ответа:
Проблема или недостающие данные:
Предложение для проверки:
Решение рекрутера, если принято:
Решение нанимающего менеджера, если принято:
```

## 5. Где искать подробности

- `04_intermediate_mas_runs/` — три отдельные более ранние попытки MAS;
  результаты разных попыток нельзя считать одним интервью.
- `90_originals/` — исходные Markdown и JSON без изменения содержания.
- `91_sources.json` — происхождение материалов, включая локальные базы.
- `92_manifest.json` — размеры и SHA-256 файлов для проверки целостности.

Исходные SQLite находились во временной папке компьютера автора. Их содержательные
данные сохранены в архиве как JSON, поэтому доступ к тому компьютеру не нужен.

Коммит передаёт архив, отчёты и инструкции. Он сам по себе не подтверждает,
что текущая версия приложения полностью воспроизводит исторические прогоны;
это отдельно проверяется по инструкции для агента.
