# AI Interviewer

Платформа для асинхронных технических интервью: рекрутёр настраивает вакансию и вопросы,
кандидат проходит интервью по персональной ссылке, а команда найма получает расшифровку,
evidence-based оценку и материалы для принятия решения.

Проект разработан для кейса Napoleon IT. Это MVP для пилотирования, а не система автоматического
найма: итоговое решение всегда принимает человек.

## Возможности

- настройка вакансии, блоков вопросов, таймеров и live coding;
- одноразовые приглашения без хранения открытого токена;
- асинхронная запись ответов с повторной загрузкой и восстановлением сессии;
- локальная или внешняя транскрибация русской технической речи;
- адаптивные follow-up вопросы и multi-agent оценка ответов;
- доказательная оценка с привязкой к цитатам, вопросам и таймкодам;
- отдельные интерфейсы кандидата, рекрутёра и нанимающего менеджера;
- кандидатский фидбэк, рейтинг внутри совместимого snapshot и поиск альтернативных вакансий;
- сигналы присутствия, смены вкладок и нескольких голосов без автоматического отказа;
- фоновые CPU/GPU workers для транскрибации, TTS и видеоаватара.

## Как работает

```text
Вакансия и требования менеджера
              ↓
      План интервью и rubric
              ↓
Персональная ссылка кандидату
              ↓
 Видеоответы, код и follow-up
              ↓
 Транскрибация и AI-оценка
              ↓
Evidence, отчёт и ручное решение
```

Система разделяет AI-рекомендацию, решение рекрутёра и решение нанимающего менеджера. Отсутствие
данных фиксируется как `insufficient_information`, а не превращается в нулевую оценку.

## Продуктовая концепция

### Проблема

При массовом найме рекрутёр не успевает содержательно проверить сотни откликов, а технические
специалисты тратят время на первичные интервью с неподходящими кандидатами. Отбор только по резюме
при этом может пропускать сильных специалистов и завышать ожидания от кандидатов с хорошо
оформленным CV, но без подтверждённых компетенций.

### Целевая аудитория

| Роль | Задача продукта |
|---|---|
| Рекрутёр | Провести единообразный первичный и технический скрининг без ручного интервью с каждым кандидатом |
| Технический эксперт | Утвердить вопросы и критерии, разбирать спорные случаи и подключаться ближе к финалу |
| Нанимающий менеджер | Быстро увидеть доказательства компетенций, пробелы и рекомендацию по следующему этапу |
| Кандидат | В удобное время продемонстрировать опыт и получить понятный результат, не ограниченный резюме |
| HR-директор / руководитель найма | Сократить стоимость и длительность воронки без потери качества и управляемости |

Первичный сегмент для пилота — команда с регулярным потоком кандидатов на техническую вакансию,
утверждённым уровнем позиции, доступным техническим экспертом и примерами прошлых интервью для
слепой калибровки.

### Ценностное предложение

> Из сотен откликов к команде доходят кандидаты с проверяемыми техническими доказательствами,
> а инженер подключается только к сложным случаям и финальному этапу.

Продукт объединяет первые этапы найма в асинхронное интервью-досье: видеоответы, код,
транскрипцию, оценку по утверждённой rubric, подтверждающие фрагменты и явно обозначенные пробелы.
AI готовит рекомендацию, но не заменяет кадровое решение человека.

## Продуктовые гипотезы

Главная гипотеза: если объединить асинхронное видеоинтервью, технические вопросы, live coding,
адаптивные уточнения и объяснимую AI-оценку, рекрутёр сможет формировать качественный shortlist за
минуты, не привлекая инженера к каждому первичному интервью.

| Приоритет | Гипотеза | Критерий проверки | RICE | Статус |
|---:|---|---|---:|---|
| 1 | Версионированная rubric и evidence к каждому выводу обеспечат воспроизводимую оценку | Согласие AI с независимой человеческой оценкой ≥80% | 65 | Требует пилота |
| 2 | Evidence cards, таймкоды и заметки ускорят работу рекрутёра | 100% оцениваемых выводов имеют evidence; просмотр отчёта ≤10 минут | 64 | Реализовано, время не измерено |
| 3 | Статус `additional_review` для нехватки данных снизит нагрузку без скрытого занижения оценки | Спорные ответы эскалируются человеку, а не получают автоматический отказ | 60 | Реализовано, эффект не измерен |
| 4 | Шесть открытых вопросов совместят биографический и технический скрининг | Завершение ≥70%, медианная длительность ≤30 минут | 60 | Требует пилота |
| 5 | AI-черновик вопросов с утверждением техническим экспертом ускорит запуск вакансии | Релевантный набор вопросов подготовлен ≤20 минут | 60 | Частично реализовано |
| 6 | Provider-neutral интеграции снизят зависимость от одного AI-поставщика | Замена совместимого провайдера занимает ≤1 рабочего дня | 40 | Архитектурно поддержано |
| 7 | Сигналы видео, нескольких голосов и смены вкладок помогут заметить риски без автоотказа | Сигналы доступны ревьюеру отдельно и имеют измеренную precision | 35 | Реализовано, precision не измерена |
| 8 | Ротация утверждённых заданий уменьшит утечки без потери сравнимости | Повторяемость вопросов снижается, межверсионная калибровка сохраняется | 24 | После MVP |

RICE используется для определения порядка проверки, а не как доказательство ценности. Баллы и
полное обоснование приведены в
[`napoleon-it-report.md`](outputs/ai-technical-interview/napoleon-it-report.md).

## Что подтверждено исследованием

Исследование включает четыре интервью с рекрутёрами и опрос 18 кандидатов. Это направляющие
сигналы для MVP, а не статистически достаточное подтверждение бизнес-эффекта.

- 77,7% опрошенных кандидатов определённо или скорее готовы пройти AI-интервью в течение семи дней;
- 72,2% предпочитают подробный разбор на 5–10 минут с примерами ошибок и рекомендациями;
- 27,8% достаточно оценки с коротким объяснением;
- при неожиданно низкой оценке 61,1% сначала сравнят вывод с собственными ответами;
- 22,2% запросят пересмотр результата человеком.

Данные поддерживают идею прозрачного асинхронного скрининга и подробного отчёта, но фактическая
конверсия, точность оценки, экономия времени и стоимость должны быть измерены на реальном пилоте.

| Ожидаемый результат | Текущее основание | Статус |
|---|---|---|
| Согласие AI и независимых экспертов ≥80% | Evidence-first схема реализована | Не проверено на целевой выборке |
| Не менее 80% приглашённых начинают и завершают интервью | Заявленная готовность в опросе — 77,7% | Поведение не проверено |
| Рекрутёр изучает результат не более 10 минут | Созданы summary, evidence cards и таймкоды | Требуется замер |
| Существенное сокращение стоимости скрининга | Есть расчётная модель 300 000 → 15 000 ₽/месяц | Допущение, не подтверждено |
| Каждый оцениваемый вывод объясним | Контракты оценки требуют evidence или статус нехватки данных | Реализовано в MVP |
| Monitoring не вызывает автоматический отказ | Сигналы отделены от профессиональной оценки | Реализовано в MVP |

## Состав MVP

В текущий контур входят:

- создание вакансии, требования менеджера, блоки вопросов и версионированные настройки интервью;
- персональные приглашения, видеоответы, транскрибация, live coding и адаптивные уточнения;
- оценка ответа по критериям с объяснением, evidence, таймкодами и состоянием нехватки данных;
- итоговый отчёт, shortlist, сравнение кандидатов, заметки и раздельные решения участников найма;
- кандидатский feedback и безопасные monitoring-сигналы без автоматического влияния на решение;
- кабинеты кандидата, рекрутёра и нанимающего менеджера.

В MVP намеренно не входят:

- автоматический отказ, автономное решение о найме или замена финального интервью;
- оценка внешности, эмоций, акцента, тембра или уверенности голоса;
- production-интеграция с Huntflow и другими ATS;
- доказанный SLA, подтверждённая экономика и финальная политика хранения персональных данных;
- промышленная защита от всех видов утечек заданий и злоупотреблений.

## Продуктовые метрики

| Группа | Что измеряем |
|---|---|
| Качество | Agreement с экспертами, macro-F1, confusion matrix, критические расхождения и баланс ошибок |
| Эффективность | Время рекрутёра, доля эскалаций эксперту, сэкономленные часы инженеров |
| Воронка | `eligible → invited → started → completed → human-approved → final` |
| Candidate UX | Завершение, длительность, технические сбои, обращения за пересмотром и удовлетворённость |
| Доверие | Доля выводов с evidence, overrides, причины несогласия и просмотр полного видео |
| Экономика | Стоимость завершённого интервью и стоимость сэкономленного часа эксперта |

## План пилота

1. Выбрать одну регулярную техническую вакансию с достаточным потоком кандидатов.
2. Подключить одного рекрутёра и минимум двух независимых технических экспертов.
3. Провести не менее 30 интервью по одной версии вопросов и rubric.
4. Сначала собрать слепые оценки экспертов, затем открыть AI-рекомендации.
5. Не использовать автоматический отказ; спорные и неполные случаи направлять человеку.
6. Измерить agreement, критические ошибки, время рекрутёра, воронку, полноту evidence,
   candidate feedback, точность monitoring-сигналов и стоимость интервью.
7. По итогам принять одно из решений: масштабировать, доработать и повторить или остановить.

## Продуктовые принципы и риски

Ключевые принципы: AI рекомендует — человек решает; evidence важнее итогового балла; резюме даёт
контекст, но не высокий технический score; отсутствие данных должно быть видимым; monitoring не
равен доказательству нарушения; технический эксперт подключается к калибровке и сложным случаям.

Основные риски пилота: ошибки AI и ASR, ложные monitoring-сигналы, bias, утечка заданий,
конфиденциальность данных, нестабильность инфраструктуры и неподтверждённая экономика. Подробные
решения, ограничения и план эксперимента находятся в
[`product-final-03-decisions-risks-and-pilot.md`](outputs/ai-technical-interview/product-final-03-decisions-risks-and-pilot.md).

## Быстрый запуск для разработки

### 1. Подготовьте окружение

```bash
cp .env.example .env
python3.12 -m venv .venv
.venv/bin/python -m ensurepip --upgrade
.venv/bin/python -m pip install -e './apps/api[workers]'
npm --prefix apps/candidate-web ci
npm --prefix apps/staff-web ci
```

В `.env` обязательно замените локальные ключи рекрутёра и менеджера. `OPENAI_API_KEY` нужен для
LLM-сценариев, но не должен попадать в Git.

### 2. Запустите инфраструктуру и миграции

```bash
docker compose up -d
PYTHONPATH=apps/api .venv/bin/python -m alembic \
  -c apps/api/alembic.ini upgrade head
```

Корневой `docker-compose.yml` запускает PostgreSQL на `localhost:5433` и MinIO на портах `9000` и
`9001`. Для функций, использующих очереди, дополнительно требуется Redis.

### 3. Запустите приложения

В отдельных терминалах:

```bash
PYTHONPATH=apps/api .venv/bin/python -m uvicorn app.main:app \
  --reload --host 127.0.0.1 --port 8000
```

```bash
npm --prefix apps/candidate-web run dev
```

```bash
npm --prefix apps/staff-web start
```

После запуска доступны:

- API и Swagger UI: `http://127.0.0.1:8000/docs`;
- health check: `http://127.0.0.1:8000/health`;
- candidate UI: `http://127.0.0.1:5173`;
- staff UI: `http://127.0.0.1:3000`.

Создать синтетическое приглашение:

```bash
PYTHONPATH=apps/api .venv/bin/python apps/api/scripts/create_demo_invitation.py
```

Скрипт напечатает URL кандидата. Используйте только синтетические данные.

## Полный Docker-стек

Production-like Compose включает API, PostgreSQL, MinIO, Redis, CPU worker, GPU presenter worker,
оба интерфейса и nginx:

```bash
docker compose -f deploy/docker-compose.prototype.yml up --build
```

GPU worker требует NVIDIA runtime, моделей XTTS/MuseTalk и локального портрета. Если presenter не
нужен, запускайте только необходимые сервисы или оставьте `PRESENTER_ENABLED=false`.

## Безопасность и ограничения

- AI не отклоняет кандидатов и не принимает кадровые решения.
- Внешность, эмоции, акцент и уверенность голоса не используются для scoring.
- Monitoring-события показываются человеку отдельно от технической оценки.
- Оценки должны ссылаться на сохранённые ответы, цитаты или таймкоды.
- Нельзя коммитить `.env`, API-ключи, записи, транскрипты, резюме и другие персональные данные.
- Исходные портреты и веса моделей хранятся локально и исключены из Git.
- До production использования качество необходимо подтвердить на отложенной выборке с независимой
  оценкой рекрутёра и технического эксперта.
